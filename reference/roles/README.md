# Roles (Matt, 2026-11-01: "a document that is out there for them alone so they understand their role and their expectations... something that they have to look at every build")

Every support helper reads its role file at the start of its session, before every build or check-in round, and after any memory
compression. The laws (reference/LAWS.md) and lessons (reference/LESSONS.md) print automatically; the role file does not, so the
brief and every check-in message say "re-read your role file first". A role file changes only through the lead.

| Role | File | Who (Nov 2) |
|---|---|---|
| Supervisor | SUPERVISOR.md | bot-fix |
| Release clerk | RELEASE-CLERK.md | kaizen-gates |
| Roadmap keeper | ROADMAP-KEEPER.md | roadmap-keeper |

All three: you report to the lead, never to Matt directly; you never merge to main, open a release PR, or spend Hugging Face money;
you are scored on reference/GAMEPLAN-2026-11-02.md §2 and retired on §3, the same as every helper.

- QUALITY-SUPERVISOR.md: judges fun, variety, challenge and use of the toolbox, in sequence like a player (Matt, 2026-11-02). Works beside the process supervisor; both talk to the helpers.
- Every role keeps reference/notes/<name>.md (reference/notes/README.md), read at start and after every compression.

- `DATA-ANALYST.md`: playthrough analysis after each play window, a ranked fix list (Matt, 11-07).

- `CONSULTANT.md`: the independent outside view (genre benchmarks against our build and data), never briefed on our reasons (Matt, 11-07).
